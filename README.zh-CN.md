# Maestro

**面向复杂软件开发的需求驱动编排。**

## 从用户的需求出发

复杂的开发工作，往往超出单次对话能承载的范围。架构决策、依赖关系、验收标准以及尚未完成的工作，都必须在上下文更替之后保留下来。

Maestro 是一个 Codex 编排技能，它把这类工作组织成一套软件工程流程。用户的需求决定架构、开发计划与验收标准。项目文档保存当前的契约与交付状态，让新的子代理能接手边界明确的任务，也让主代理能依据记录在案的证据继续协调工作。

## 共同澄清需求

在新项目、新阶段开始之前，或者需求发生重大变更时，Maestro 会先进行一次追问式讨论（grilling）。它会梳理出彼此依赖的决策，一次性提出所有目前可以回答的问题，并为每个问题推荐答案。负责调查的代理会查证仓库中的事实，产品层面的取舍则由用户决定。

相关的决策分支都有结论之后，Maestro 会总结出共识，请用户明确确认。这份共识是初始化、架构设计与任务规划的依据。已确认的结论会沿用到小改动和恢复的工作中；一旦出现新的歧义，就重新打开受影响的分支。该协议随 Maestro 一并提供。

## 一个阶段怎么走

![Maestro 阶段流程图 —— 讨论需求、确认共识、初始化阶段、设计架构、规划任务，重复分派与验收的循环，然后审查、确认并归档该阶段。纠正回路和剩余任务回路会把工作送回适当的步骤。](docs/assets/stage-flow.jpg)

- 在初始化之前**讨论并确认**需求：把相关的决策树讨论清楚，并确认双方理解一致。
- 在分派之前，依据这份共识**设计**架构、**规划**任务图。
- **执行**依赖已经就绪的任务，每次都用新的执行者。未通过验收的任务，先诊断原因，再重试同一任务。记录并提交已验收的工作，然后选择下一个就绪任务。
- 审查阶段成果，逐项处理未完成的需求：能完成的直接完成，需要调整范围的则先取得明确批准，然后**结束**该阶段。确认结束后，归档交接材料，并规划下一阶段。

主代理在工作流或阶段初始化、实质性流程变更、讨论交接记录保存或更新，以及阶段归档完成后，各做一次范围明确的本地 Git 提交。任务验收方面，核心或高风险任务卡每卡独立提交；紧密相关的 `luna-max` / `sol-medium` 小卡支持按“小批次/子里程碑”合并提交，减轻拆细卡带来的流程负担。

## 执行过程中如何保持协调

主代理负责架构决策、先摸底再拆细任务卡、分级调度、共享记录、集成和最终验收。每个执行者只负责一张任务卡，按卡内给出的代码路径、实施步骤和防跑偏红线施工。相互独立的任务可以并行执行，默认最多同时运行两个实现执行者；彼此耦合的工作按依赖顺序推进。

路由坚持“**先拆细、先写清，向下默认选档；选高配必须举证**”——把确定性的调研、纯工具、UI 文案、清理、测试与契约已定实现主动拆给中低端模型，减少全员高配通胀。随附的九个中文配置按层级差异化了指令：

| 模型 | 推理等级 | 典型工作 |
| --- | --- | --- |
| Luna | max | 只读代码调研、纯工具/类型模块、UI 文案、死代码清理、单测补齐与文档同步 |
| Sol | medium · high · xhigh · max | `medium` 负责契约清晰的标准功能与适配；`high` 及以上专注跨模块状态联动、事务安全与疑难排障 |
| Astra | medium · high · xhigh · max | 存在明显设计不确定性的方案权衡、跨系统架构推理与高风险核心攻关 |

确有高复杂度或高设计不确定性时可以直接从高配起步，但须在路由理由中说明为何不能拆细降级。验收失败时，先诊断根因属于需求、环境、实现还是推理层面。完整拆卡与路由规则见[执行者路由指南](references/worker-routing.md)。

## 上下文更替后继续推进

全套技能与模板均采用平实清晰的中文，同时服务“持续把控进度与方向的人类”和“零上下文开工的执行者”。需求文档先写背景痛点与明确不做，进度文档提供任务状态看板、阻塞项、待拍板决策与已知技术债，任务卡固化实施步骤、禁区约束与可执行验证命令。

| 持久化上下文 | 用途 |
| --- | --- |
| 架构与决策 | 跨阶段传递核心设计原则、模块代码定位、关键决策与跨阶段技术债 |
| 阶段需求与任务 | 保存背景目标、排除边界、依赖图、模型分层概览与可直接施工的任务卡 |
| 进度与验收记录 | 提供一眼可读的进度看板、阻塞项、方向变更与可复核的实测证据 |
| 已归档的阶段与交接 | 保留已交付能力、变更、遗留技术债，以及下一阶段的讨论输入 |

验证力度与改动风险相匹配，有效证据在执行者自检、主代理评审与阶段收尾之间直接复用。`scripts/validate_workflow.py` 在保持对旧阶段文档完全向后兼容的同时，会把缺少实施步骤/禁区、缺具体路径或验证命令、粒度过大、高配未举证与全员高配等质量问题全部以 `WARN` 暴露出来。完整规范请参见[文档契约](references/document-contracts.md)。

## 安装

将仓库克隆到你的 Codex 技能目录，然后安装执行者配置。

```bash
git clone https://github.com/JAY201368/maestro.git ~/.codex/skills/maestro
mkdir -p ~/.codex/agents
cp ~/.codex/skills/maestro/assets/worker-profiles/*.toml ~/.codex/agents/
```

安装或更新配置后，请新建一个会话，以便 Codex 能识别这些配置。使用以下方式调用该技能：

```text
$maestro
```

描述你期望的结果，并提供已有的需求或项目文档。Maestro 会先和你一起澄清尚未确定的决策，再确认共识。Maestro 可以适配仓库现有的文档路径。可用的模型和运行时设置取决于你的 Codex 环境。
